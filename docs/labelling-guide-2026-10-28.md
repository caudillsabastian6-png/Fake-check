## One card at a time, in this exact order
1. Take the next pair in pool file order (front shot, then back shot, pair by pair).
2. Loop preps: front photo + back photo + proposed label.
3. Owner Yes tap OR a thumbs-up on the card message counts as approved in the
   in-chat review. A correction reply counts as NOT approved. Duplicate
   taps/reactions on the same card count once.
4. After the loop, Potion may finalize a clear label herself under the authority
   above. Only finalized cards move forward. Log every finalization the same day with:
   name, printed number, front file, back file, genuine/fake/unknown, set status.

## Label fields — every card gets all of these
- Name (as printed on the card)
- Printed number (e.g. 119/156 — the number beats any name guess)
- Set: read the set symbol FIRST from the bottom of the card's own front photo
  (owner correction, Oct 28, 2026 ~5:21 PM), then match symbol + printed number
  to the catalogue for the exact set name, then show the filled set to the owner
  in a second pass before it counts. Sets are never a blocker for the first Yes,
  which locks name / number / genuine / pair.
- Front file + back file (exact filenames, never renamed in the label)
- Genuine / fake / unknown: genuine only where the owner confirmed it;
  fake only where the owner confirmed it; everything else is UNKNOWN.
- Condition: UNKNOWN unless the owner said it in his own words. Record his words
  only, never turn them into a grade. Example, Oct 28, 2026: owner observed
  scratches all over the Rocky Helmet holo, and visible holo scratches on a
  couple of earlier reviewed cards — recorded as his observation, not a grade,
  and no earlier card was singled out because he did not name it.

## Guards — never break these
- Never pair a guessed or generic back with a specific front.
- Never guess a set, a name, or an identity from file order. Scans stay a
  separately labelled SCAN set, never silently merged into phone-photo ground truth.
- Front-only items are filed back MISSING, never given a made-up back.
- Tier C reference/web material never decides a label alone.
- Pending / unverified material never enters the genuine (A) or fake (B) piles.
  A Potion-finalized label under the Oct 28 ~5:51 PM authority is NOT pending —
  it is finalized for identity/pair only, and its genuine/fake field follows the
  authority rule above (owner-confirmed source, else UNKNOWN).
- A photo grade is never claimed as read from the owner's photos, and a label
  is never claimed as a verdict. Verdicts stay gated: matcher + threshold +
  calibration re-run + Latch review, all separate decisions.

## AUTO-LABEL RULE — Oct 28 ~10:36 PM ET, owner order
- Scanner does NOT type labels. Potion/crew auto-label, scanner only taps "Is this correct?" Yes / No.
- If they don't know and you don't know, DON'T GUESS — but still label what you CAN.
- Partial labels are the rule: each field is labelled separately, unknown fields stay UNKNOWN, never filled with a guess.
- Priority order, owner-set: (1) NUMBERS AT THE BOTTOM are the most important — printed number (e.g. 010/198) first. (2) Same with the LOGO — set symbol at the bottom, read off the card's own photo. (3) Same with the NAME — card name, only if clear.
- A label with a clear number + clear logo, but unknown name, still counts as a partial label and still files to pending. A label with nothing clear files as UNKNOWN, not as a guessed card.
- No = label drops to UNKNOWN for the disputed field(s), never kept as a wrong label, Potion corrects later.
